# Tool Registry

Document every reusable local tool, script, workflow, or API helper here.

## Registered Tools

| Tool | Location | Purpose | How to Use | Inputs | Outputs | Notes |
| --- | --- | --- | --- | --- | --- | --- |
| Context snapshot | `scripts/context_snapshot.sh` | Print the core project knowledge packet for a new conversation. | `./scripts/context_snapshot.sh` | None | Markdown sections from the core knowledge files. | Run before planning or executing substantial work. |
| Public CLOB check | `src/commands/check-public.ts` | Verify Polymarket CLOB connectivity without account credentials. | `npm run check:public` | Optional `.env.local` values `POLYMARKET_CLOB_HOST`, `POLYMARKET_CHAIN_ID`. | JSON with host, chain, CLOB OK status, server time, version, and first-page market count. | Read-only; verified on 2026-06-18 against `https://clob.polymarket.com`. |

| Polymarket US public check | `src/commands/us-check-public.ts` | Verify Polymarket US public API access without credentials. | `npm run us:check-public` | None. | JSON with sample active events, markets, and sport count. | Read-only; verified on 2026-06-18 against `https://gateway.polymarket.us`. |
| Polymarket US account check | `src/commands/us-check-account.ts` | Confirm Polymarket US authenticated account access without creating/canceling orders. | `npm run us:check-account` | `.env.local` with `POLYMARKET_US_KEY_ID` and `POLYMARKET_US_SECRET_KEY`. | JSON with balances, open-order count, and position count. | Read-only authenticated endpoints only. |
| Research web tool | `src/server.ts` | Local browser UI for running the leader consensus screen, trader-quality/history screen, strong-trader current-position watch, sharp-disagreement screen, and Kalshi public market search. | `npm start`, then open `http://127.0.0.1:8787` | Consensus inputs for leaderboard cohort, expiry window, agreement threshold, entry rule, concurrency, and page depth. Trader-quality inputs for leaderboard cohort, minimum history filters, API page depth, cache TTL, refresh, and concurrency. Strong-watch inputs for leaderboard cohort, cached Q threshold, expiry window, minimum position value, opposition filter, concurrency, and page depth. Sharp-disagreement inputs for sharp Q, weak Q, inferred topic-fit, expiry, position value, cache coverage, and opposition filters. Kalshi inputs for query, status, result count, close window, minimum volume, combo filter, and optional orderbook depth. | Browser-rendered consensus candidates, leader/opposing rows, cached `Q` badges, trader-quality ranking table with odds-adjusted edge and odds buckets, high-Q current-position markets, sharp-vs-opposed market rows, inferred topic fit, Kalshi public market quotes/orderbooks, aligned/opposed leader groups, and warnings. | No credentials required. Keep concurrency low (`1`-`2`) for interactive Polymarket scans; high concurrency can cause public Data API timeouts. Trader-quality cache lives at `data/cache/trader-quality.json`; Strong Trader Watch and Sharp Disagreement depend on that cache. Kalshi Markets is read-only public API access. User guide: `docs/user-tools.md`. |
| Kalshi public market search | `src/kalshi/public-api.ts` | Search public Kalshi markets and optionally fetch displayed orderbook levels. | Web endpoint: `POST /api/kalshi-markets` through `npm start` | `query`, `status`, `limit`, `closeWithinDays`, `minVolume`, `mveFilter`, `includeOrderbook`, `orderbookDepth`. | JSON result with market ticker, title, status, close time, YES/NO quotes, spread, last price, volume, liquidity, combo flag, and optional orderbook summary. | No credentials required. Uses official public REST endpoints under `https://external-api.kalshi.com/trade-api/v2`. Search and close-window filtering are local over the fetched page. |
| Strong trader watch engine | `src/polymarket/strong-trader-watch.ts` | Find current public positions held by cached high-Q traders and show which scanned leaderboard traders are aligned or opposed in the same market. | Web endpoint: `POST /api/strong-watch` through `npm start` | `top`, `category`, `timePeriod`, `orderBy`, `asOf`, `withinDays`, `qualityThreshold`, `minPositionValue`, `maxPagesPerTrader`, `concurrency`, `onlyWithOpposition`. | JSON result with market/outcome candidates, strong traders, aligned leaders, opposed leaders, signal score, score components, and warnings. | Uses only the latest matching Trader Quality accepted list for the same top/category/window/rank cohort, avoiding stale Q scores from other screens. Public current positions only; does not fetch or expose other traders' open orders. Research-only signal, not a trade recommendation. |
| Sharp disagreement engine | `src/polymarket/sharp-disagreement.ts` | Find current markets where high-Q traders with topic-specific fit hold one side and other leaderboard traders oppose them. | Web endpoint: `POST /api/sharp-disagreement` through `npm start` | `top`, `category`, `timePeriod`, `orderBy`, `asOf`, `withinDays`, `strongQualityThreshold`, `weakQualityMax`, `minTopicScore`, `minPositionValue`, `maxPagesPerTrader`, `concurrency`, `requireWeakOpposition`. | JSON result with sharp side, inferred topic, sharp/aligned/opposed leaders, weak-opposition counts, entry discount, signal score, score components, and warnings. | Uses topic summaries in `data/cache/trader-quality.json`; run Trader Quality with refresh first. Topic is inferred from title/slug keywords and should be treated as a screening aid. |
| Internal consistency bench | `src/commands/internal-consistency.ts` | Validate local invariants behind cache reuse and screen handoffs. | `npm run test:consistency` | None. | PASS/FAIL terminal output. | Offline test bench. Currently checks Trader Quality cache scope filtering, stale-badge rejection, unscoped badge loading, and topic inference categories. |
| Leaderboard trader pull | `src/commands/leaderboard-traders.ts` | Pull public leaderboard traders and save wallet/profile IDs for later workflows. | `npm run leaderboard:traders -- --top 100 --json data/leaderboards/overall-day-pnl-top100.json` | Either `--top` or `--from`/`--to`; optional `--category`, `--time-period`, `--order-by`, `--json`, `--csv`. | JSON manifest with `ids` and `traders`; optional CSV. | No credentials required. Uses `/v1/leaderboard` with 50-row pages; leaderboard offset is limited by API docs. |
| Leader consensus screen | `src/commands/consensus-leaders.ts` | Find near-term markets where leaderboard traders mostly agree and compare current price to their entry range. | `npm run consensus:leaders -- --top 20 --time-period DAY --within-days 5 --entry-rule within-range` | Optional `--top`, `--category`, `--time-period`, `--order-by`, `--as-of`, `--within-days`, `--agreement`, `--min-leaders`, `--min-position-value`, `--entry-rule`, `--max-pages-per-trader`, `--json`, `--csv`. | JSON consensus manifest; optional CSV of candidate markets. | No credentials required. Public API can be slow; command retries and records page-truncation warnings. Research-only, not a trade recommendation. |
| Trader quality screen | `src/commands/trader-quality.ts`, `src/polymarket/trader-quality.ts` | Score leaderboard traders using public trade, closed-position, and current-position history; warm cached `Q` badges for the web consensus screen. | `npm run trader:quality -- --top 20 --json data/quality/top20.json --csv data/quality/top20.csv` | Optional `--top`, `--category`, `--time-period`, `--order-by`, `--min-volume`, `--min-roi-pct`, `--min-trades`, `--min-markets`, `--min-closed-markets`, `--trade-pages`, `--closed-pages`, `--current-pages`, `--cache-hours`, `--refresh`, `--cache`, `--json`, `--csv`. | JSON quality manifest; optional CSV; local cache at `data/cache/trader-quality.json`; odds-adjusted metrics and odds-bucket rows. | No credentials required. Uses public `/trades`, `/closed-positions`, and `/positions`. Odds edge uses settlement-consistent terminal rows only, share-weights expected/actual outcome rates, and keeps ROI cost-weighted. Held/sold/hedged metrics are inferred from available public rows and should be treated as screening signals, not accounting truth. |
| User positions pull | `src/commands/positions-user.ts` | Pull all current public Data API positions for a wallet/profile address with pagination. | `npm run positions:user -- --user 0x...` | Required `--user`; optional `--top`, `--sort-by`, `--sort-direction`, `--size-threshold`, `--market`, `--event-id`, `--json`, `--csv`. | JSON terminal summary; optional full JSON and CSV files. | No credentials required. Uses `/positions` with 500-row pages; warns via `hitOffsetLimit` if the documented offset ceiling is reached. |

## Registration Rule

When adding a tool, include:

- What problem it solves.
- Exact command or entry point.
- Required environment variables or credentials.
- Expected inputs and outputs.
- Examples for the common path.
- Known limitations, rate limits, or safety constraints.
- How to verify it still works.
