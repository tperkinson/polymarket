# Polymarket Account Automation

This is the first local infrastructure layer for accessing Polymarket accounts through official APIs.

## Scope

- Uses `@polymarket/clob-client-v2` for the international CLOB API.
- Uses `polymarket-us` for the Polymarket US API.
- Supports public connectivity checks for both API families.
- Supports L1 wallet signing to create or derive international CLOB L2 API credentials.
- Supports read-only authenticated account checks for both API families.
- Does not place orders, cancel orders, bridge funds, withdraw funds, bypass regional restrictions, or automate the Polymarket web UI.

## Setup

```bash
npm install
cp .env.example .env.local
```

Set these values in `.env.local`.

For Polymarket US:

- `POLYMARKET_US_KEY_ID`: developer portal Key ID.
- `POLYMARKET_US_SECRET_KEY`: developer portal Secret Key.

For the international CLOB API:

- `PRIVATE_KEY`: wallet key used locally for signing.
- `POLYMARKET_SIGNATURE_TYPE`: wallet type. For current new API/deposit-wallet flows, this is usually `3`.
- `POLYMARKET_FUNDER_ADDRESS`: required for proxy, Safe, or deposit-wallet flows.
- `CLOB_API_KEY`, `CLOB_SECRET`, `CLOB_PASS_PHRASE`: generated by the derive command.

## Commands

```bash
npm start
```

Starts the local web frontend at `http://127.0.0.1:8787`. The page has `Consensus Screen`, `Trader Quality`, and `Strong Trader Watch` tabs. They use public Data API workflows on the local server and render candidates, leader details, quality badges, trader-history metrics, strong-trader current positions, aligned/opposed leaderboard traders, and warning messages in the browser.

Parallelism note: leaderboard calls are lightweight, but position scans can be slow or time out under heavy parallelism. Keep `concurrency` at `1` or `2` for interactive use. Higher values may finish faster when the endpoint is healthy, but the scanner may record truncation warnings if requests time out.

The Trader Quality tab writes cached public-history metrics to `data/cache/trader-quality.json`. The consensus screen reads that cache and shows a `Q` badge beside trader names when a score is available. Run Trader Quality first to populate those badges.

The Strong Trader Watch tab also reads the quality cache. It filters for cached high-Q traders, pulls current public positions for the selected leaderboard cohort, groups by market/outcome, and shows which scanned leaderboard traders are aligned or opposed.

```bash
npm run consensus:leaders -- --top 20 --time-period DAY --within-days 5 --entry-rule within-range --json data/consensus/overall-day-pnl-top20-next5.json
```

Screens public leaderboard traders for near-term consensus positions. It pulls leaderboard trader IDs, scans their largest current positions, groups positions by market/outcome, and keeps markets where the configured agreement threshold is met.

Useful options:

- `--agreement 0.8`: require at least 80% of positioned leaders in a market to agree on the outcome.
- `--min-leaders 2`: require at least two positioned leaders in a market. Use `3` or higher for stronger consensus.
- `--within-days 5`: only include markets ending within the next five days from `--as-of`.
- `--entry-rule within-range`: require current price to be inside the agreeing leaders' average-entry range. Use `at-or-below-weighted` or `none` for broader screens.
- `--max-pages-per-trader 1`: scan the largest current-value page per trader; raise this for deeper but slower scans.

```bash
npm run trader:quality -- --top 20 --json data/quality/overall-day-pnl-top20.json --csv data/quality/overall-day-pnl-top20.csv
```

Scores public leaderboard traders and warms the local quality cache used by the web UI. It pulls leaderboard rows, recent trades, closed positions, and current positions, then computes sample-size, ROI, odds-adjusted resolved edge, odds-bucket performance, held-to-resolution, sold-before-resolution, and hedging metrics.

Useful options:

- `--min-volume 1000`: require a minimum leaderboard volume.
- `--min-roi-pct 0`: require non-negative leaderboard ROI percentage.
- `--min-trades 50`: require at least 50 fetched trades.
- `--min-markets 10`: require at least 10 fetched markets.
- `--min-closed-markets 5`: require at least 5 fetched closed markets.
- `--trade-pages 1`: fetch 500 `/trades` rows per trader.
- `--closed-pages 2`: fetch 100 `/closed-positions` rows per trader.
- `--current-pages 1`: fetch 500 current `/positions` rows per trader.
- `--cache-hours 6`: reuse cached history for six hours.
- `--refresh`: ignore cached history and fetch again.

```bash
npm run leaderboard:traders -- --top 100 --json data/leaderboards/overall-day-pnl-top100.json
```

Pulls public leaderboard trader IDs and metadata into a manifest that later workflows can use to pull positions, trades, or activity. This does not require account credentials.

Range form:

```bash
npm run leaderboard:traders -- --from 51 --to 100 --json data/leaderboards/overall-day-pnl-51-100.json
```

Useful options:

- `--category OVERALL`: category. Other documented values include `POLITICS`, `SPORTS`, `CRYPTO`, `TECH`, and `FINANCE`.
- `--time-period DAY`: window. Other values are `WEEK`, `MONTH`, and `ALL`.
- `--order-by PNL`: ranking field. Use `VOL` for volume.
- `--csv data/leaderboards/file.csv`: export a spreadsheet-friendly copy.

The JSON output includes:

- `ids`: flat list of `proxyWallet` addresses.
- `traders`: rank, wallet, username, PnL, volume, and profile metadata.

```bash
npm run positions:user -- --user 0x...
```

Pulls all current public Data API positions for a wallet/profile address. This does not require account credentials.

Common export form:

```bash
npm run positions:user -- --user 0x... --json data/positions/user.json --csv data/positions/user.csv
```

Useful options:

- `--top 25`: include more rows in the terminal summary.
- `--sort-by CURRENT`: sort by current value. Other documented values include `INITIAL`, `TOKENS`, `CASHPNL`, and `PERCENTPNL`.
- `--size-threshold 0`: include dust positions. This is the command default.
- `--market 0x...` or `--event-id 123`: limit results to a market or event.

```bash
npm run us:check-public
```

Checks Polymarket US public API access without credentials.

```bash
npm run us:check-account
```

Uses `POLYMARKET_US_KEY_ID` and `POLYMARKET_US_SECRET_KEY` to call read-only Polymarket US account, order-list, and portfolio endpoints.

```bash
npm run check:public
```

Checks international CLOB availability and fetches the first simplified markets page without credentials.

```bash
npm run auth:derive -- --write-env .env.local
```

Uses `PRIVATE_KEY` for L1 signing, creates or derives CLOB L2 API credentials, and updates only the CLOB credential keys in `.env.local`.

```bash
npm run account:check
```

Uses `PRIVATE_KEY` plus L2 API credentials to call read-only authenticated CLOB account endpoints.

## Polymarket US Passkey Flow

A macOS passkey for `polymarket.us` is useful for signing in to the Polymarket US developer portal. It is not itself an API credential and cannot be copied into `.env.local`.

1. Visit `https://polymarket.us/developer`.
2. Sign in with the same method used in the iOS app. For a saved passkey, macOS should prompt for Touch ID or local approval.
3. Create an API key.
4. Copy the Key ID into `POLYMARKET_US_KEY_ID`.
5. Copy the Secret Key into `POLYMARKET_US_SECRET_KEY`. The secret is shown only once.
6. Run `npm run us:check-account`.

## Safety Notes

- Keep `.env.local` local. It is ignored by git.
- Do not paste private keys or CLOB secrets into chat.
- Do not paste Polymarket US API secrets into chat.
- Confirm your account type before setting `POLYMARKET_SIGNATURE_TYPE` and `POLYMARKET_FUNDER_ADDRESS`.
- Treat eligibility, platform access, account rules, and regional availability as current-source questions, not assumptions.
